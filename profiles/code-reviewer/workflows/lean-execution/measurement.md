# Local measurement procedure
This is agent-maintained accounting, not an installed automatic collector or background monitor. The orchestrator owns ledger.json; workers write isolated receipts in task artifact directories. No separate template is required. Each receipt records run_id, task_id, profile, stage, session_id, model, provider, usage_source, input_tokens, output_tokens, cached_tokens, elapsed_seconds, cost, currency and billing_source. Keep unavailable values null; exclude credentials and raw content. Do not log raw prompts, responses, credentials or private business content.

Each run has a unique run_id, parent task_id, profile, stage (orchestration/implementation/review/repair/research/design/operations), session evidence, and observed model/provider. Read usage from available runtime/provider records, not model guesses. Final usage may become available only after exit; default can fill it from records. Record observed request/cache counts without assuming provider field semantics; describe the source. Never initiate an extra model call just to estimate cost.

Record per-run costs only with currency and actual billing source. Subscription usage is separate; do not invent per-task dollar cost. Unavailable data stays null. Avoid double counting parent totals that already include children, duplicate resumed sessions or auxiliary usage. State accounting scope explicitly, including whether auxiliaries are captured. Maintain task-level acceptance separately from worker self-reports. Failed attempts, repair and review costs remain part of the task. Preserve incomplete/failed tasks in cohort reports, not only successes.

The orchestrator appends/merges sequentially by run_id and task_id; never concurrent writes to the central ledger. On tasks with concurrent orchestrators, keep separate task ledgers and consolidate later. Use deterministic aggregation. Cost per accepted task across a defined cohort includes all observed run costs for that cohort (including failed tasks), divided by independently accepted tasks, with matching currency and accounting scope. If any relevant cost is unknown, show a known subtotal and missing coverage, not a complete cost or savings rate. A cohort with no accepted tasks has no defined cost per accepted task.

For later user testing, compare representative software, research, UX and business read-only tasks under fixed models/settings and explicit acceptance criteria. Keep held-out cases. Measure correctness/coverage, retries, elapsed time and cost together. Do not claim improvement from the rollout itself. Never modify business records just for a benchmark.
